# Asteriade 投資研究特化への設計方針（ドラフト）

- 記録日: 2026-10-21
- 状態: **レビュー用提案 / 未マージ**。本書は既存の v1.1 要件定義をまだ置換しない。
- 目的: 研究の方向性・判断理由・未解決事項を別のAIや次の開発セッションへ引き継げるようにする。
- 対象市場（初期候補）: 暗号資産、FX、日経225mini。市場別の契約仕様・時間帯・コストモデルは分離する。

## 1. 方向転換と基本原則

Asteriade の初期製品は、汎用的な開発エージェント管理画面ではなく、**自律的な投資仮説の研究・反証・バックテスト支援システム**とする方向で検討する。汎用的なAI実行・権限・予算・履歴管理の内部基盤は再利用可能にしてよいが、初期UIと主要な研究機能は投資特化とする。実売買・注文自動化は初期範囲外。

研究目的は「好成績が出るまでパラメータを調整すること」ではない。市場構造に基づく反証可能な仮説を立て、独立した批判と再現可能な実験によって優位性の有無を検証する。否定的結果も研究成果とする。研究が失敗した際には理由を記録して次の研究テーマへつなげるが、無制限の探索や合格基準の事後緩和はしない。

## 2. マルチAI討論：Manager最終判断方式

AIは多数決で結論を決めない。高性能なManager AIが研究計画と最終判断を担当し、低コストの独立Reviewerが専門的な反論を行う。可用性・認証・料金を確認した許可済みモデルのみ使用する。

**1つの仮説に対する討論は以下の5ステップ、再反論は最大1回。**

1. Managerが仮説、理論的根拠、研究対象、検証計画、採否条件を提示。
2. Reviewerが**互いの意見に依存せず**独立評価。反論が無ければその旨を明記してよい。
3. Managerが指摘ごとに、採用・一部採用・却下・実験で確認を選び、根拠を付して回答。合理的な指摘は素直に認め、異論があれば実質的な再反論を行う。
4. ReviewerはManagerの回答に対し、**重要な未解決点のみ**再反論。論点の言い換えや無意味な反対は禁止。
5. Managerが採用・改訂・実験設計・保留・棄却を最終決定し、理由、未解決点、次の行動を記録。

Round 2が不要なら省略。Reviewer間の全員一致・Managerへの無制限再照会を要求しない。意見の相違は比較実験として扱う。討論の最大回数・再試行回数・予算・待機時間は**モデルの自制ではなくオーケストレーターが強制**する。モデル応答なし、判断不能、構造化出力の不備も有限回の再試行後に明示的な状態へ遷移させる。

Managerの最終判断は尊重するが、未来情報漏洩、検証エンジン不具合、保護データの無許可アクセス、権限違反、予算制限などの**機械的な品質・安全ゲートは上書きできない**。

独立レビュアーの観点候補: 論理、市場メカニズム、統計/多重検定、約定/コスト、リスク、機会損失、探索範囲の不足。初期版は役割を増やしすぎず、必要な観点をまとめた少数のAIで運用できるようにする。

## 3. 研究の状態遷移・進行管理

基本の研究ループ:

`仮説生成 → 独立レビュー → Manager回答 → 必要なら再反論 → Manager最終決定 → 実験定義の凍結 → Codex実装/実行 → 機械的な評価 → 結果解釈 → 次の仮説`

- Project / Hypothesis / ResearchCycle / Experiment を区別し、実行と会話のIDを付与する。
- 研究全体の費用・時間・試行上限を設け、議論や微修正が永続ループしないようにする。
- 既存仮説の無意味なパラメータ微調整が続く場合、別の市場現象・時間軸・方法への転換を検討する。
- 「候補なし」はサイクル単位では有効な結果。研究セッション全体を閉じるかは残予算・探索範囲・新情報・停止条件で判断する。
- AIの発言だけで実行済み/終了済みにしない。Runnerの実行記録、検証完了イベント、成果物の存在と整合性を事実のソースとする。

## 4. 研究・実験エンジン

責務を分ける。

- AI Research Team: 仮説発見・論点整理・実験計画・結果の解釈。
- Experiment Engine: 共通の取引会計、約定モデル、バックテスト、統計検証、データ・実装の再現性。
- Research Governor: 権限、コスト、回数、研究データ境界、状態遷移、証拠監査。

戦略は Entry / Exit / Position Management / Risk・Sizing を可能な範囲で独立部品化する。GAは必要時に呼び出す最適化・探索ツールであり、研究判断そのものの代替ではない。Grid/Random/GA/探索なし等を計画段階で選択し、選択理由と未探索の方法を残す。

GAの探索空間には明示的に対象を定義する。Entryだけに限定したGAでExitまで探索したと誤認しない。分割エントリー、トレーリングストップ、部分決済、複数ポジションなどの検討状況をカバレッジ記録へ残す。ただし全組合せを総当たりする義務はない。計算量と多重探索リスクを考慮し段階的に評価する。

### 取引コストと損失分布

- 悲観的な一律コストだけで全戦略を失格にしない。根拠のある**基準コスト**、好条件、ストレス条件を別々に報告する。
- コストは手数料/スプレッド/スリッページ/資金調達料・スワップ等に分解する。急変時の執行コストと市場状態の相関に留意する。
- 高リターン・高リスク研究を許容する選択肢を設ける。固定DD閾値をすべての投資方針へ強制しない。
- 全損確率、テール損失、破産確率、資金配分による損益分布と推定の不確実性を評価する。配分資金を超える損失もシミュレーション上は明示し、決して「損失上限保証」と表示しない。
- **高リスク許容は、統計的不備・未来情報混入・不正確な約定仮定の免除ではない。**
- 期待値のあるルールの検証とレバレッジ/資金配分の最適化を分けて説明する。

### 品質ゲート

- 合成データによる損益検算、取引時計、約定順序、ロング/ショート、欠損、時系列リーク、契約単位のテスト。
- 探索期間 / 評価期間 / 最終確認用データの隔離。事前に定義した評価指標と基準を結果確認後に変更しない。
- 最終確認データにアクセスしたか、結果がAI/人間の意思決定へ露出したか、科学実装のバグが発生したかを記録する。
- バグによる中断時は無条件で「一生使えない」または「未使用に戻せる」としない。独立性・修正範囲・値露出の事実を区別して判定する。
- 戦略・コード・データ・設定・乱数seed・実験結果にidentity/hashを紐付ける。未使用データがない場合は「独立した最終検証は未完了」と明記する。
- 複数仮説を試した事実を保存し、最良結果の選択バイアスを考慮する。

## 5. Research Cockpit（投資研究に特化したUI）

「AI稼働台数」よりも**何を研究し、なぜ、今どこまで進み、次に何が起こるか**を優先表示する。

画面を開いたとき最低限わかること:

1. 現在の仮説（自然言語で説明）と市場・足種・方向・背景。
2. 現在フェーズ（議論/計画凍結/実装/バックテスト/結果確認/次の研究）。
3. 次のバックテスト開始までの残り**具体的工程**。不確実な所要時間をでっち上げない。
4. 実Runnerが稼働中か、バックテスト完了か、検証無効か、Managerが分析中か。
5. 現在の担当、次の行動、ユーザー承認が要るか、停止理由。
6. 主要結果、棄却・保留の理由、関連する証拠と過去の類似研究。

進捗表示の真実源は、保存済み状態遷移、Runnerイベント、検証済み成果物。詳細なAI討論・ログは折りたたみ可能とする。研究ステップだけではなくプロジェクト・研究サイクル・実験の3階層を表示。左側に市場/プロジェクト一覧を保持する。

## 6. 記録と引き継ぎ（必須）

次のセッションや別AI・別アプリへ文脈なしでも渡せるよう、Markdownと機械可読JSONを保存する。

最低限の記録:

- 研究の目的、スコープ、モデル・レビュアーの役割、承認済み制約。
- 仮説IDと因果説明、批判、Manager応答、再反論、最終判断と理由。
- 探索カバレッジ: 試したもの / 試さなかったもの / その理由。
- 実験定義・データ期間・取引コスト想定・選択規則・全候補の結果。
- データ由来・履歴・時刻規約・コード/設定hash・乱数seed・再現手順。
- 最終Holdoutの状態・値と結果の露出記録・修正と科学的欠陥。
- 否定的結果・既知の限界・再利用可能なコード・次の仮説候補。
- GitHub・外部ストレージ・ローカル成果物への参照、保存期限、消失時の再現不能の明記。

研究サイクルの区切り、実験完了、研究計画変更、重大なバグ検出、作業セッション終了時に更新する。会話本文の丸ごと保存だけに依存しない。

## 7. 旧BTC研究からの具体的な教訓

- 以前のGAは特徴量の論理構造探索であり、Entry/Exit/Position全体を同時最適化したものではなかった。
- 後段では部分決済・トレーリング等の研究も行われていた。**各フェーズで何を探索したかを人間に明示**する。
- 旧研究の最終Holdoutでは科学実装の不具合が見つかり、無傷の最終検証としては扱わず修正版の分析に分類した。この区別をAsteriade内で管理する。
- CIの短期保持Artifactのみでは再現に必要な元データ・全実験成果物の長期保管が保証できない。長期保存先を設け、検証済みの参照とハッシュを残す。
- 過去の研究ロジックとテストの再利用可能性は検討するが、実装可能性・互換性は未確認。

## 8. 実装スコープと保留事項

初期は市場データ・検証エンジンの品質と、1市場での end-to-end 研究サイクルを優先。実売買は対象外。月額の追加従量費用、サンドボックス、ユーザー承認、通知ポリシーは既存の安全方針を維持する。

**未解決（推測で固定しない）**

- 各市場の優先順位、利用するデータ源とデータ保持方式。
- プロジェクトをまたいで研究対象を自律的に変更できる範囲。
- リスク/リターン目的関数、戦略の研究対象期間、ポジション管理の研究スコープ。
- Python製の既存検証Runnerをどの範囲で再利用するか。
- 実装モデルごとの現行API、認証、契約、料金、権限境界の検証。
