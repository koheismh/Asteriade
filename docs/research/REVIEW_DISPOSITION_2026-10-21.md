## 採用した指摘

| 提案 | 判断 | 反映内容 |
|---|---|---|
| 仮説選択の優先順位 | 採用 | 市場構造の根拠、競争・持続性、反証可能性、執行/費用、情報価値、研究履歴を比較。AIスコアを実際の成功確率とは呼ばない。 |
| 多数の仮説・研究サイクルによる過学習 | 採用 | ResearchProgram・Projectをまたぐ候補系譜/選抜集合/試行履歴を保持。統計手法は前提に合わせる。 |
| 適切な比較対象 | 採用 | 研究前に基準戦略を少なくとも1つ登録し、費用/リスク/資本拘束を踏まえ相対評価する。 |
| 将来データでの検証 | 採用 | ルール凍結後の観測だけをProspectiveとして保存し、過去データの遡及を禁止。実注文は伴わない。 |
| 戦略と共通の会計エンジンを分離 | 採用 | versioned StrategySpecを介し、価格時計・約定・手数料・会計は固定カーネル。変更には別のテスト/監査が必要。 |
| 複数AIの有用性の実測 | 採用 | 3方式（単一AI/単一AI＋コード検査/討論＋同じ検査）の品質・費用・速度を後から比較。 |
| 研究の費用対効果 | 採用 | 有効実験率、欠陥検出率、研究時間、データ/モデル/計算費、介入回数、独立評価成績などを追跡。 |
| 実用性を確認する受け入れテスト | 採用 | 参照実装、意図的バグ、無優位性データ、ベンチマーク、討論比較、Prospective等を追加。 |

## 一部採用・保留の指摘

| 提案 | 判断と理由 |
|---|---|
| MVPでは単一AIだけにする | **部分採用**。実験は1市場・単純なエンジンから始める。ただし独立Reviewerとの有限の討論はユーザーが明示した中核要件なので、Stage 1に残す。全専門Reviewerを毎回常駐させる必要はない。 |
| Freqtrade/Backtrader等の導入 | **比較評価のみ採用**。既存OSS/旧quant-btc-labの再利用を検討するが、Windows配布・ライセンス・市場仕様・実測精度を確認せず採用しない。 |
| PBO/Deflated Sharpe/Reality Checkを必須化 | **手法を条件付き候補として採用**。対象データ・標本数・相関・研究目的を確認して選ぶ。全手法を全実験に機械的に適用しない。 |
| 複数AI討論を必須でなくす | **保留/一部反映**。標準討論は維持。効果を測り、必要なら起動Reviewerの人数・専門性・頻度を調整する。 |
| 論文名から特定の研究能力を断定 | **採用しない**。AlphaForgeBench、FINSABER、その他引用研究は、この改訂で個別の存在・内容まで確認していない。要件は論文の真偽に依存させない。 |

## 維持した方針

- Research Managerの最終判断、初回独立レビューと再反論は最大2ラウンド。
- 仮説、現在フェーズ、次のバックテストまでの工程を一目で確認できるResearch Cockpit。
- 一律の極端な取引コスト/低DDだけで高リスク・高リターンの研究を自動棄却しない。
- 投資枠の全損リスクやテール損失は分析するが、予想リターンや損失上限を保証しない。
- Holdoutの露出管理と科学実装バグの監査は初期から必須。実際の取引・発注は初期対象外。

- 月間従量費上限、Windowsローカル優先、GitHubへの研究引き継ぎ、公開文書に個人の金融情報を書かない。
