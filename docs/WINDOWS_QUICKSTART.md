# Asteriade Stage 0 — 最初の動作確認

この ZIP には、Windows x64 用 EXE、ソース一式、手順書が含まれます。
**最初は Go をインストールせず、EXE の動作確認だけで構いません。**

## 1. 展開と起動

1. ZIP を完全に展開してください。ZIP 内から直接実行しません。
2. 展開した `Asteriade-Stage0` フォルダで PowerShell を開きます。
3. 通常ユーザーとして次を実行します。エラーを読めるよう、最初は端末から起動してください。

```powershell
.\bin\asteriade.exe
```

管理画面がブラウザに開きます。自動で開かない場合は、端末に表示された `launch-*.html` の場所を開いてください。
起動リンクは10分・1回限りです。リンクの内容を共有しないでください。

## 2. 確認すること

- 画面が開き、Stage 0、Runner 未検証、実行無効が表示される。
- 目標を1件保存でき、一覧とイベントに表示される。
- 全体と Project の一時停止を両方作り、Project 分だけ再開しても全体の一時停止が残る。
- 端末で Ctrl+C により終了し、同じコマンドで起動し直すと、目標・イベント・停止理由が残る。
- 同じデータ領域で2つ目を起動すると、DB ロックにより2つ目が終了する。確認後は元のアプリを通常終了する。

**自律実行ができない状態が、この版では正常です。**
この確認は管理画面と保存基盤の確認であり、Windows sandbox や実際の AI 実行の安全性検証ではありません。

## 3. 報告する内容

次の形式で結果を知らせてください。失敗した項目だけでも構いません。

```text
Windows 11 のバージョン / OS ビルド:
起動・画面表示: 成功 / 失敗
目標の保存: 成功 / 失敗 / 未実施
全体と Project の一時停止・再開: 成功 / 失敗 / 未実施
終了・再起動後の保存内容: 残る / 消える / 未実施
同じ保存領域の二重起動: 拒否される / 起動できてしまう / 未実施
エラー本文・補足:
```

Windows のバージョンと OS ビルドは `winver` で確認できます。
起動エラーがある場合は PowerShell のエラー本文を報告してください。保存領域の権限を緩めたり、管理者起動に切り替えたりする必要はありません。
起動リンク、Cookie、CSRF token、個人の認証情報は報告に含めないでください。

## 4. 追加のソース検証（任意）

`scripts\verify-windows.ps1` は、Go のテスト・ビルドと結果記録を行う追加手順です。
**EXE だけでは実行できず、同梱のソース一式と公式 Go 1.27.2 Windows amd64 が必要です。**
ソース検証も行う場合は、Go を導入してから展開先のルートで次を実行します。

```powershell
.\scripts\verify-windows.ps1
```

実行ポリシーに拒否された場合はポリシーを無効化せず、そのエラーを報告してください。
成功時の結果は `.local\validation\manifest.json` と `go-test.jsonl` です。失敗時はエラー本文と、生成されていれば結果ファイルを確認してください。
詳細は `docs\WINDOWS_VALIDATION.md` にあります。ソース検証が通っても自律実行は有効になりません。
